# IPv6及IPv6+网络技术培训课程

 获课：jzit.top/26811/IPv6及IPv6+网络技术培训课程

地址与 SID 规划——转发改造的地基工程
核心观点：SRv6 落地失败最常见的根因不是协议不会配，而是地址与 SID 规划缺乏全局约束；规划必须先于设备选型与业务割接，且要预留十年演进空间。

SRv6 中，SID 本身就是 IPv6 地址，转发行为由地址前缀决定。这意味着"地址规划"与"转发策略规划"合二为一，一旦规划失当，后期调整的代价远高于传统网络。工程上应建立分层规划模型。

第一层，编址空间分区。 建议按"基础设施段、云资源段、业务段、SRv6 SID 专用段"划分 IPv6 地址空间，并在运营商/集团层面统一分配，避免各云池、各地域自行其是。SID 专用段应独立于普通终端地址段，便于在转发面做差异化处理与安全策略。每个云池、每个网络域获得连续子段，为后续聚合路由与跨域互通留出余地。

第二层，SID 类型与长度规划。 SRv6 常见 SID 类型包括：节点段（End）、邻接段（End.X）、VPN 段（End.DT4/DT6）、服务段（End.AS 等）。规划需明确：哪些类型启用、各自占用的地址块、Locator 长度如何设定。Locator 过短则单域可分配 SID 数量不足，过长则压缩效率与可读性下降。实践中应按"域内可聚合、跨域可识别"原则设计 Locator，并使 Locator 与拓扑位置有一定对应关系，便于故障定位与路由聚合。

第三层，SID 与业务/租户的映射策略。 云网融合中，VPN 段 SID 往往需要按租户或业务实例分配。要提前决定：是按"每租户独立 SID 块"（隔离性好、消耗大），还是"共享 SID 块+实例标识"（节省、依赖映射表）。前者适合大型政企专线，后者适合海量中小租户。该决策直接影响边界设备的表项规模与转发性能。

第四层，与既有编址的共存与迁移。 现网大量使用 IPv4 与 MPLS，SRv6 改造期必然长期共存。规划应明确双栈策略、IPv4 业务如何通过 SRv6 承载（如 End.DT4 映射）、MPLS 域与 SRv6 域的互通点与映射方式，避免"新域自成一体、旧域无法接入"。

规划落地还需要工程约束：建立 SID 分配管理系统，任何 SID 启用须登记用途、归属、生命周期；规划文档与 CMDB、IPAM 联动，防止手工配置漂移；预留至少一倍余量的地址块应对业务增长。度量上应跟踪 SID 利用率、聚合度、跨域路由条目数。地基打牢，后续云内与网内改造才有稳定的坐标系。
